## รันบนเครื่องตัวเอง

ต้องมี Node 20.9 ขึ้นไป และ PostgreSQL (จะรันเองหรือใช้ Supabase ก็ได้)

```bash
npm install
cp .env.example .env.local      # แล้วแก้ค่าใน .env.local
npm run db -- init              # สร้างตารางจาก ../schema.sql + migrations
npm run db -- seed              # ใส่ข้อมูลตัวอย่าง (ข้ามได้ถ้าจะใส่ของจริงเลย)
npm run dev                     # เปิด http://localhost:3000
```

ค่าที่ต้องตั้งใน `.env.local` มีสี่ตัว อธิบายไว้ใน `.env.example` ทั้งหมด
**ห้าม commit `.env.local`** — มันถูก gitignore ไว้แล้ว

สุ่ม `SESSION_SECRET` ด้วย:

```bash
openssl rand -hex 32
```

## ใช้ Supabase

1. สร้างโปรเจกต์ใหม่ที่ supabase.com
2. คัดลอก connection string จาก Project Settings → Database มาใส่ `DATABASE_URL`
   (ใช้แบบ **Session pooler** เวลา deploy บน Vercel)
3. `npm run db -- init` จะสร้างตารางทั้งหมดให้เอง — ไม่ต้องกดอะไรในหน้าเว็บ Supabase

## เปิดทดสอบจากมือถือในวงเดียวกัน

Next บล็อกการโหลดไฟล์ dev จาก origin อื่นโดยค่าตั้งต้น ถ้าจะเปิดจากมือถือ
ให้ใส่ IP ของเครื่องลง `DEV_ORIGINS` ใน `.env.local` แล้วรัน `npm run dev` ใหม่

```
DEV_ORIGINS=192.168.1.20
```

แล้วเปิด `http://192.168.1.20:3000` บนมือถือ (บน production ไม่มีข้อจำกัดนี้)

## คำสั่งที่มี

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | รัน dev server |
| `npm run build` / `npm start` | build และรันแบบ production |
| `npm run typecheck` | ตรวจ TypeScript ทั้งโปรเจกต์ |
| `npm run smoke` | ทดสอบชั้นคำนวณเงินกับฐานข้อมูลจริง (สร้างและลบข้อมูลของตัวเอง) |
| `npm run test:e2e` | ทดสอบผ่านเบราว์เซอร์จริงทั้ง 3 ชุด — ดู "ชุดทดสอบ" ข้างล่าง |
| `npm run db -- init \| migrate \| seed \| reset` | จัดการฐานข้อมูล — `reset` ลบข้อมูลทั้งหมด |

**ถ้ามีข้อมูลจริงอยู่แล้ว อย่าใช้ `reset`** ใช้ `npm run db -- migrate` แทน
มันจะรันเฉพาะไฟล์ใน `../migrations/` ที่ยังไม่เคยรัน

`npm run smoke` ต้องชี้ไปที่ฐานข้อมูล **dev เท่านั้น** มันเขียนและลบข้อมูลจริง

## โครงไฟล์

```
src/lib/
  env.ts        อ่านค่าจาก environment — ไม่มีที่อยู่หรือรหัสผ่านอยู่ในโค้ดเลย
  db.ts         ตัวเชื่อม PostgreSQL ตัวเดียวทั้งแอป
  session.ts    cookie ล็อกอินแบบเซ็น HMAC (ใช้ได้ทั้ง edge และ node)
  auth.ts       signIn / signOut / requireSession
  status.ts     สถานะงานและธง "รอเรา / รอลูกค้า" — กติกาหลักของทั้งระบบ
  format.ts     เงินบาทและวันที่แบบไทย
  queries.ts    SQL ทั้งหมดที่หน้าเว็บใช้ — คิดเงินด้วย numeric แล้วค่อยแปลงตอนแสดง
  actions.ts    server action ทุกตัวที่เขียนข้อมูล
src/app/        หน้าเว็บ (App Router)
src/components/ ชิ้นส่วน UI ที่ใช้ซ้ำ
proxy.ts        กันคนที่ยังไม่ล็อกอินออกจากทุกหน้า ยกเว้น /login
tools/          สคริปต์ฐานข้อมูลและ smoke test
tests/          ชุดทดสอบผ่านเบราว์เซอร์จริง (Playwright)
```

## ชุดทดสอบ

| ชุด | ครอบคลุมอะไร |
|---|---|
| `tests/core.mjs` | ล็อกอิน · หน้าแรก · บอร์ด · เปิดงาน · รับเงิน · ลงต้นทุน · ลูกค้า · **หน้าการเงิน** |
| `tests/leads.mjs` | หน้าคนทัก · อัตราปิด · CPL · เปิดงานจากคนทัก · เหตุผลที่ไม่ซื้อ |
| `tests/renewals.mjs` | หน้าต่ออายุ · ชุดเตือน 30/14/7/1 · cron · การต่ออายุ · **สิทธิ์เข้าถึง API** |

หน้าการเงินทดสอบ**ความสัมพันธ์** (กำไร = รายรับ − รายจ่าย และหน้าแรกต้องบอกเลขเดียวกัน)
ไม่ใช่ตัวเลขตายตัว เพราะชุดทดสอบสร้างงานกับรายจ่ายของตัวเองระหว่างทาง

```bash
npm run build && npm start &          # หรือ npm run dev
npm run test:e2e                      # ทั้งหมด
npm run test:e2e leads                # เฉพาะชุดเดียว
```

ทุกชุด **reset + seed ฐานข้อมูลก่อนรันเสมอ** จึงต้องชี้ไปที่ฐานข้อมูล dev เท่านั้น
รหัสผ่านอ่านจาก `.env.local` ไม่ได้ฝังไว้ในไฟล์ทดสอบ

ต้องมี Playwright กับ Chromium ในเครื่อง ถ้าติดตั้งไว้คนละที่:

```bash
export PLAYWRIGHT_PACKAGE=/path/to/playwright/index.js
export CHROME_PATH=/path/to/chrome
```

## ค่าโฆษณานับจากไหน

ลงได้สองที่ และระบบเลือกให้เอง ไม่นับซ้ำ:

| ที่เก็บ | มาจากไหน | ใช้เมื่อ |
|---|---|---|
| `ad_spend_daily` | นำเข้า CSV รายวันรายแคมเปญ (เฟส 4) | เดือนนั้นมีข้อมูล → ใช้อันนี้ |
| `expenses` kind = `ads` | กรอกมือในหน้างาน | เดือนนั้นไม่มีรายวัน → ใช้อันนี้ |

นิยามอยู่ที่ `adSpendBetween()` ใน `src/lib/queries.ts` **ที่เดียว**
หน้าแรก หน้าการเงิน หน้าคนทัก และไฟล์ส่งออก เรียกผ่านมันหมด จึงบอกตัวเลขเดียวกันเสมอ
(ไฟล์ส่งออกรวมค่าโฆษณาจาก `ad_spend_daily` เป็นบรรทัดเดียวต่อเดือนต่อแคมเปญ
และข้าม `expenses kind='ads'` ของเดือนนั้นไป — ยอดรวมจึงกระทบกับหน้าการเงินได้)

`npm run smoke` มีข้อทดสอบที่ล็อกเรื่องนี้ไว้ 6 ข้อ ถ้าเผลอแยกนิยามอีกจะไม่ผ่าน

## ไฟล์แนบเก็บไว้ที่ไหน

อยู่ในฐานข้อมูลเป็น `bytea` ในตาราง `attachments` ไม่ใช่ object storage
เพราะแบบนี้ Postgres ที่รันเองกับ Supabase ทำงานเหมือนกันโดยไม่ต้องตั้งค่าเพิ่ม
และไม่พังเวลาโฮสต์ล้างดิสก์ทุกครั้งที่ deploy

จำกัดไฟล์ละ 5MB รับเฉพาะรูปกับ PDF ที่ขนาดนี้ สลิปกับสกรีนช็อตทั้งปีก็ยังไม่ถึงร้อยเมกะไบต์
ถ้าวันหนึ่งมันโตเกินนั้น ย้ายเนื้อไฟล์ไปเก็บที่อื่นแล้วให้ตารางนี้เป็นดัชนีแทน —
คอลัมน์ที่มีอยู่พอสำหรับเก็บ key ของ bucket อยู่แล้ว

## ตั้งค่าแจ้งเตือนต่ออายุ

ระบบจะเตือนล่วงหน้า **30 / 14 / 7 / 1 วัน** ก่อนวันหมดอายุ (วันที่มาก่อนระหว่างโดเมนกับโฮสต์)
ปรับจำนวนวันได้ที่ `RENEWAL_REMINDER_DAYS`

ถ้ายังไม่ตั้งช่องทางไหนเลย ระบบยังทำงานได้ปกติ — หน้าต่ออายุยังบอกทุกอย่าง
แค่ไม่มีข้อความส่งเข้ามือถือ

### Telegram (ง่ายที่สุด ใช้เวลา 10 นาที)

1. ทักหา `@BotFather` ใน Telegram แล้วพิมพ์ `/newbot` จะได้ token มา
2. ทักบอทตัวเองหนึ่งครั้ง
3. เปิด `https://api.telegram.org/bot<token>/getUpdates` แล้วหาเลข `chat.id`
4. ใส่ `TELEGRAM_BOT_TOKEN` กับ `TELEGRAM_CHAT_ID` ใน `.env.local`

### LINE Official Account

สร้าง LINE OA แล้วเปิด Messaging API เอา channel access token กับ user id มาใส่
`LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_USER_ID`
(**LINE Notify ปิดบริการไปแล้วเมื่อ มี.ค. 2025** อย่าไปหาตัวนั้น)

### ให้มันเตือนเองทุกวัน

`vercel.json` ตั้ง cron ไว้ที่ `0 2 * * *` ซึ่งเป็น **UTC** = 09:00 น. เวลาไทย
ตั้ง `CRON_SECRET` ให้ยาวและสุ่ม แล้วใส่เป็น environment variable บน Vercel ด้วย —
ถ้าไม่ตั้ง ปลายทาง `/api/cron/renewals` จะปิดตายแทนที่จะเปิดให้ใครก็เรียกได้

ถ้าไม่ได้ deploy บน Vercel ให้ยิงเองด้วย cron อะไรก็ได้:

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://<โดเมนของคุณ>/api/cron/renewals
```

งานนี้รันซ้ำได้ไม่พัง — มันจดไว้ว่าเตือนอะไรไปแล้วสำหรับวันหมดอายุรอบไหน
และจะบันทึกว่า "ส่งแล้ว" ต่อเมื่อส่งออกสำเร็จจริง ถ้าส่งไม่ออกจะเงียบไว้แล้วลองใหม่รอบหน้า

## สิ่งที่ยังไม่มีในเฟสนี้ (ตั้งใจ)
- **คนที่ทักมา แคมเปญ และ CPL/CAC** — เฟส 4 (ตาราง `leads`, `ad_*` มีใน schema แล้ว)

  และเขียนกำกับไว้ตรงนั้นว่ายังไม่รวมค่าโฆษณา

## หมายเหตุเรื่องความปลอดภัย

- ระบบนี้เก็บข้อมูลส่วนบุคคลของลูกค้า อย่าเปิดให้เข้าถึงได้โดยไม่ล็อกอิน
  และอย่าใช้รหัสผ่านซ้ำกับที่อื่น
- **ห้ามเก็บรหัสผ่านของลูกค้าไว้ในช่องบันทึก** ตาราง `websites` มีช่อง
  `credential_ref` ไว้ชี้ไปที่ password manager แทน (เฟส 3)
- คิดถึง backup ตั้งแต่วันแรก — ระบบนี้จะกลายเป็นที่เดียวที่มีข้อมูลลูกค้าทั้งหมด
