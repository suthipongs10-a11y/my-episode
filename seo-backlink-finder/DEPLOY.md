# Deploy ที่ไหนดี — คำตอบตรง ๆ

**สรุปก่อน: รันบนเครื่องคุณเองหรือบน VPS ครับ ไม่ใช่ Cloudflare Workers และไม่ใช่ Vercel**
เหตุผลอยู่ข้างล่าง คุณบอกว่าเน้นคุณภาพงาน — และตัวเลือกทั้งสองข้างบนทำให้คุณภาพลดลง
โดยไม่ได้อะไรกลับมาเลยสำหรับงานประเภทนี้

---

## 1. ทำไม Cloudflare Workers ไม่เหมาะ

Workers ออกแบบมาสำหรับ request สั้น ๆ ที่ตอบเร็ว งานของเราตรงข้ามทุกข้อ:

| ข้อจำกัดของ Workers | งานเราต้องการ |
|---|---|
| CPU time ต่อ request จำกัด (free 10ms, paid 30s–5 นาที) | ตรวจ 60 เว็บ ใช้เวลาหลายนาทีถึงชั่วโมง |
| ไม่มี Python runtime เต็ม (Python Workers ยัง beta, ไม่มี `lxml`) | ใช้ `lxml`/`beautifulsoup4` แกะ HTML |
| ไม่มี filesystem, SQLite ต้องเปลี่ยนไป D1 | เก็บงานลง SQLite ตรง ๆ |
| IP ของ Cloudflare ถูกเว็บจำนวนมากบล็อกหรือให้ CAPTCHA | ต้องดึงหน้าเว็บเป้าหมายให้สำเร็จ |
| งานยาวต้องแตกเป็น Queues + Durable Objects | ตอนนี้เป็น loop ธรรมดา |

**จะทำได้ไหม?** ได้ ถ้าเขียนใหม่เกือบทั้งหมดเป็น JavaScript + D1 + Queues + Durable
Objects — งานหลายสัปดาห์ แลกกับเครื่องมือที่ **ดึงเว็บได้แย่ลง** เพราะ IP ถูกบล็อกบ่อยกว่า
นั่นคือจ่ายแพงเพื่อให้ได้ของที่คุณภาพต่ำลง ผมจึงไม่แนะนำ

## 2. ทำไม Vercel ก็ไม่เหมาะ (แต่เหมาะกว่านิดหน่อย)

Vercel รัน Python ได้จริง แต่เป็น serverless function:

- **Timeout**: Hobby 60 วินาที, Pro 300 วินาที (5 นาที) — ตรวจ 60 เว็บไม่ทันแน่นอน
- **Stateless**: ไฟล์ที่เขียนหายทุก request → SQLite ใช้ไม่ได้ ต้องต่อ Postgres ข้างนอก
- **ต้องแตกงาน**: ต้องทำเป็น job queue + cron ซึ่งซับซ้อนขึ้นมาก
- **ค่าใช้จ่าย**: การรันยาว ๆ บน serverless แพงกว่า VPS เล็ก ๆ หลายเท่า

จะใช้ Vercel ได้ก็ต่อเมื่อแยกเป็น "หน้าเว็บบน Vercel + worker จริงที่อื่น" ซึ่งก็แปลว่า
คุณต้องมี VPS อยู่ดี — งั้นเอา VPS อย่างเดียวจบกว่า

## 3. ที่แนะนำ: เครื่องคุณเอง หรือ VPS ที่มีอยู่แล้ว

### 3.1 บนเครื่องคุณ (ง่ายที่สุด เริ่มได้เลย)

```bash
cd seo-backlink-finder
pip install -e .
blf init                 # แก้ config.yaml
blf serve                # เปิด http://127.0.0.1:8080
```

**ข้อดี**: ตั้งค่าใน 2 นาที, ใช้ IP บ้านคุณ (เว็บบล็อกน้อยกว่า IP ดาต้าเซ็นเตอร์มาก),
ไม่มีค่าใช้จ่าย, ข้อมูลอยู่กับคุณ
**ข้อเสีย**: ต้องเปิดเครื่องไว้ตอนรัน

### 3.2 บน VPS ด้วย Docker (เหมาะถ้าอยากให้รันทิ้งไว้)

คุณมี Hostinger VPS อยู่แล้ว (จาก CLAUDE.md) ใช้ตัวนั้นได้เลย:

```bash
git clone <repo> && cd seo-backlink-finder
mkdir -p data && cp config.example.yaml data/config.yaml
cp config.example.env .env        # ใส่ API key ถ้ามี
docker compose up -d
```

เปิดที่ `http://127.0.0.1:8080` **ผ่าน SSH tunnel** (ดูข้อ 4)

**ข้อดี**: รันทิ้งไว้ได้, resource จำกัดชัดเจน, ย้ายเครื่องง่าย
**ข้อเสีย**: IP ดาต้าเซ็นเตอร์โดน CAPTCHA บ่อยกว่าเน็ตบ้าน

## 4. ⚠️ เรื่องความปลอดภัยที่ต้องอ่าน

**หน้าเว็บ UI นี้ไม่มีระบบล็อกอิน** และมันสั่งให้เซิร์ฟเวอร์ไปดึง URL อะไรก็ได้
ถ้าเปิดออกอินเทอร์เน็ตตรง ๆ ใครก็ตามที่เจอมันจะ:

- สั่งให้เซิร์ฟเวอร์คุณยิง request ไปเว็บใดก็ได้ (ใช้เป็นเครื่องมือโจมตีคนอื่นได้)
- อ่านและแก้ข้อมูลเป้าหมายทั้งหมดของคุณ

`docker-compose.yml` จึงผูกไว้กับ `127.0.0.1` เท่านั้นโดยตั้งใจ วิธีเข้าใช้งานที่ถูก:

```bash
# จากเครื่องคุณ — อุโมงค์ SSH ไปที่ VPS
ssh -L 8080:127.0.0.1:8080 user@your-vps
# แล้วเปิด http://127.0.0.1:8080 บนเครื่องคุณ
```

ถ้าจำเป็นต้องเปิดสาธารณะจริง ๆ ให้วาง reverse proxy (Caddy/nginx) ที่มี
Basic Auth หรือ Cloudflare Access ไว้หน้าสุดก่อนเสมอ **อย่าเปลี่ยน `127.0.0.1`
เป็น `0.0.0.0` โดยไม่มีการยืนยันตัวตน**

## 5. Cloudflare ยังมีประโยชน์ตรงไหน

ถ้าวันหนึ่งคุณทำ**หน้าเว็บสาธารณะ**ให้เครื่องมือนี้ (ให้คนอื่นใช้ สมัครสมาชิก จ่ายเงิน)
สถาปัตยกรรมที่ถูกคือ:

```
Cloudflare (CDN + DDoS + Access)  →  หน้าเว็บ/แดชบอร์ด
                                        ↓ API
                                   VPS ที่รัน worker จริง  ←  งานดึงเว็บทั้งหมดอยู่ตรงนี้
```

Cloudflare อยู่หน้าส่วนที่เป็น HTTP ธรรมดา ส่วนงานคลานเว็บอยู่บน VPS เสมอ
นี่คือรูปแบบเดียวกับที่ `CLAUDE.md` §3c สรุปไว้สำหรับโปรเจกต์ RO server ครับ —
Cloudflare ป้องกันสิ่งที่เป็น HTTP ไม่ใช่สิ่งที่ต้องรันยาว ๆ

## 6. สรุปตาราง

| ที่ | ใช้ได้ไหม | ควรใช้ไหม |
|---|---|---|
| **เครื่องคุณเอง** | ✅ ทันที | ⭐ **เริ่มที่นี่** — คุณภาพการดึงเว็บดีที่สุด |
| **VPS + Docker** | ✅ ทันที | ⭐ ถ้าอยากรันทิ้งไว้ / ใช้ VPS ที่มีอยู่ |
| **Vercel** | ⚠️ ต้องแยก worker ออกไปอยู่ดี | ❌ ได้ไม่คุ้มเสีย |
| **Cloudflare Workers** | ⚠️ ต้องเขียนใหม่ทั้งหมด | ❌ คุณภาพแย่ลง งานเยอะขึ้น |
| **Cloudflare หน้าเว็บสาธารณะ** | ✅ | ✅ เมื่อทำเป็นบริการให้คนอื่นใช้ |
