## รอบล่าสุดทำอะไรไป

### ทิศทางใหม่ — จาก audit ที่ลูกค้าขอ ไปเป็น outbound prospecting (รอบนี้)

ผู้ใช้ต้องการ flow: **ค้นหาธุรกิจ → Active? → ยิง Ads? → เปิดเว็บ → Audit →
Opportunity score → Problems → Quick wins → Proposal → ส่ง Email**

| ขั้น | สถานะ | ทำอะไรรอบนี้ |
|---|---|---|
| เปิดเว็บ · Audit · Problems | มีอยู่แล้ว | — |
| **ยิง Ads?** | ✅ ฟรี | `crawl/signals.ts` จับ Meta Pixel / Google Ads tag / TikTok / LINE Tag / GTM จาก HTML · `07-serp` บันทึก `ownPaid` (ลูกค้าโผล่ในผล paid) |
| **Active?** | ✅ ครึ่งแรก ฟรี | parked/placeholder (ไทย+อังกฤษ) · ปีลิขสิทธิ์ (แปลง พ.ศ.) · ลิงก์ social · reachable — **อีกครึ่ง (รีวิวล่าสุด, เวลาทำการ) รอ Places key ใน M4** |
| **Opportunity score** | ✅ | `scoring/opportunity.ts` — deterministic, 4 ส่วน (pain/budget/alive/reach) + veto (parked/เข้าไม่ได้) + **`pitch`** = มุมที่ควรเปิดเรื่อง เลือกจากข้อเท็จจริง ไม่ใช่ให้ LLM เดา |
| **Quick wins** | ✅ | `quickWins()` = impact ≥ 6 และ ≤ 3 ชม. เรียงตามผล/ชม. |
| ค้นหาธุรกิจ | ❌ รอ Places key | Text Search ตามหมวด+พื้นที่ → คิวงานอัตโนมัติ |
| Proposal | ❌ รอ LLM key (M5) | LLM เขียนจาก `pitch` + quick wins + findings — **ห้ามผลิตตัวเลข** เหมือนเดิม |
| ส่ง Email | ❌ **ต้องตัดสินใจก่อน** | ดูหัวข้อถัดไป |

stage ใหม่ `09-presence` (ตามสเปกเดิมของ M4 แต่ทำเฉพาะสัญญาณที่ฟรี) ·
opportunity เก็บเป็น snapshot แยก `site/opportunity` **ไม่มีวันไปโผล่ในรายงานลูกค้า** ·
dashboard มีคอลัมน์ "โอกาส" + การ์ดพร้อม pitch, ads, social, quick wins

### ⚠️ ขั้น "ส่ง Email" ชนกับกฎข้อ 8 ของโปรเจกต์ — ต้องให้ผู้ใช้ตัดสินใจ

`CLAUDE.md §8` เขียนไว้ว่า *"ส่งรายงานให้เฉพาะคนที่กรอกฟอร์มเอง ห้ามยิง audit แล้วส่งหาคนที่ไม่ได้ขอ (PDPA)"*
flow ใหม่คือ audit คนที่ไม่ได้ขอแล้วส่งอีเมลหา — ตรงข้ามกัน

**ข้อเสนอที่ทำให้อยู่ร่วมกันได้** (ยังไม่ได้ implement รอตัดสินใจ):
1. อีเมลที่ส่งออกเป็น **ข้อเสนอสั้น ๆ + quick win 1–2 ข้อ** ไม่ใช่รายงานเต็ม
   → รายงานเต็มส่งเมื่อเขาตอบกลับ/ขอ = กฎเดิมยังอยู่ครบ
2. ส่งเฉพาะ **อีเมลธุรกิจ/role** (info@, contact@, sales@) ไม่ส่งหาชื่อบุคคล
3. **ฉบับเดียว** มี opt-out ชัดเจน จดรายชื่อที่ปฏิเสธถาวร
4. **คนกดส่งเองทีละฉบับ** หลังอ่าน draft — ไม่ auto-send · เก็บ log ว่าส่งอะไรหาใครเมื่อไหร่

ถ้าตกลงตามนี้ ให้แก้ §8 ของ CLAUDE.md ให้ตรงกัน แล้วค่อยสร้าง email queue

### scoring v3 — คะแนนรวม 30 จาก 62 แต้มเป็นค่าสมมติ (รอบก่อนหน้า)

ผู้ใช้รันกับเว็บลูกค้าจริงแล้วส่งภาพมา: **เปลี่ยนคนดูเป็นคนทัก 78 · โครงสร้าง 82 ·
เทคนิค 80 แต่คะแนนรวมได้ 62** — ต่ำกว่าทุกแท่งบนหน้าจอ บอกว่า "งง"

ถูกแล้วที่งง เพราะมันผิดจริง v2 แก้แค่ครึ่งเดียว: หมวดที่ไม่ได้วัดคืน 50 แทน 0
(ไม่ถูกตัดสินว่าสอบตกแล้ว) **แต่ 50 นั้นยังถูกถ่วงน้ำหนักเต็มในค่าเฉลี่ยอยู่ดี**

- วัดได้จริง: conversion 25% + onpage 10% + technical 5% = **40%**
- ค่าสมมติ 50: local 25% + content 20% + visibility 15% = **60%**
- ⇒ **30 จาก 62 แต้มไม่ได้มาจากการวัดอะไรเลย** ขัดกับกฎข้อ 1 ตรง ๆ

**v3: เฉลี่ยเฉพาะหมวดที่วัดได้ แล้ว renormalise น้ำหนัก** เว็บเดียวกันได้ **79** —
"เท่าที่เราดู เว็บนี้ได้เท่านี้" ซึ่งเป็นตัวเลขที่ขยับเมื่อการวัดขยับเท่านั้น

มีเทสต์ reproduce เคส 62→79 ตรง ๆ และเทสต์ property ว่า **คะแนนรวมต้องไม่ต่ำกว่า
ทุกหมวดที่วัดได้** ซึ่งเป็นอาการที่คนอ่านเห็นแล้วรู้ทันทีว่าพัง

### กราฟและข้อมูลเพิ่ม

- **แถบ coverage ใต้ตัวเลขใหญ่** — 79 ที่วัดครบ กับ 79 ที่วัดไป 40% เป็นคนละคำกล่าวอ้าง
- **กราฟ "ปัญหาอยู่ตรงไหนบ้าง"** — แท่งซ้อนต่อหมวด แยกสีตามความรุนแรง เรียงจากมากไปน้อย
  ตอบ "ควรเสนอขายหมวดไหนก่อน" ซึ่งรายการที่เรียงตามความคุ้มค่าตอบไม่ได้
  (legend เสมอ · ช่องว่าง 2px คั่นด้วยสีพื้นไม่ใช่เส้นขอบ · ค่าอยู่ท้ายแท่ง)
- **ชั่วโมงงานรวม + จำนวนหน้า** — ใช้ตีราคางานได้ทันที

### บั๊ก Windows — ทุกคำสั่งใช้ไม่ได้เลย (รอบก่อนหน้า)

ผู้ใช้รัน `pnpm dash` บน Windows แล้ว **เด้งกลับ prompt ทันที ไม่มี error ไม่มีอะไรเลย**

สาเหตุ: ตัวเช็คว่า "ไฟล์นี้ถูกรันตรง ๆ หรือถูก import"

```ts
if (import.meta.url === `file://${process.argv[1]}`)   // ✗
```

บน Linux `argv[1]` = `/home/u/app/server.ts` เอา `file://` ต่อหน้าแล้วบังเอิญตรงกับ
`import.meta.url` พอดี · บน Windows `argv[1]` = `C:\Users\...\server.ts`
(backslash, มี drive letter, ไม่มี slash นำ) ส่วน `import.meta.url` =
`file:///C:/Users/.../server.ts` — **ไม่มีทางตรงกัน เงื่อนไขไม่เคยเป็นจริง
โปรแกรมจึงจบด้วย exit 0 เงียบ ๆ**

กระทบ **ทั้ง 4 คำสั่ง**: `pnpm dash`, `pnpm audit`, `pnpm worker`, `pnpm ctx`
แก้ด้วย `packages/core/src/entry.ts` → `isEntryPoint()` ที่ใช้ `pathToFileURL`

**ทำไมเทสต์ 304 ข้อจับไม่ได้:** เทสต์รันบน Linux ซึ่งบั๊กนี้เกิดไม่ได้ · และ
เทสต์เรียก `main()`/`createApp()` ตรง ๆ ไม่เคยผ่านตัว guard เลยสักครั้ง
งานทุกรอบที่ผ่านมา "ตรวจแล้ว" บน Linux ทั้งหมด

**ที่กันไว้ตอนนี้:** `entry.test.ts` มีเทสต์ที่ `git grep` ทั้ง repo หา
`` `file://${process.argv `` — ถ้ามีใครเขียนแบบเดิมอีก เทสต์แดงทันที
(รูปแบบ Windows จำลองบน Linux ไม่ได้ เพราะ `pathToFileURL` แปลง path ข้ามแพลตฟอร์มไม่ได้
เทสต์จึงพิสูจน์ได้แค่ครึ่งเดียว — ตัว grep คือด่านจริง)

### ล็อกอิน + พร้อม deploy (รอบก่อนหน้า)

`pnpm dash` เดิมไม่มีระบบล็อกอิน ซึ่งเป็นสิ่งเดียวที่ขวางการเอาขึ้นเว็บ —
ทุกทางเลือกของการ host ต้องใช้เหมือนกัน เลยทำก่อน

- `apps/web/src/auth.ts` — รหัสผ่านเดียวจาก `DASHBOARD_PASSWORD`
  session เป็นคุกกี้ที่เซ็น HMAC พร้อมวันหมดอายุ **ไม่มีตาราง session**
  เปลี่ยนรหัส = session เก่าตายหมดทันที (secret มาจากรหัสผ่านถ้าไม่ได้ตั้ง `SESSION_SECRET`)
- throttle การเดารหัส นับต่อ IP · เทียบรหัสแบบ constant-time
- `Dockerfile` + `.dockerignore` — host ไหนที่รับ Docker ก็ deploy ได้
- `docs/deploy.md` — 3 ทางที่ใช้ได้จริง + 1 ทางที่ใช้ไม่ได้ พร้อมเหตุผล

**กฎที่สำคัญที่สุดของรอบนี้:** ถ้า `WEB_HOST` ไม่ใช่ loopback แล้วไม่ได้ตั้งรหัสผ่าน
**เซิร์ฟเวอร์จะไม่ยอมขึ้นเลย** (`assertSafeToBind`) — ไม่ใช่แค่ warn ใน log
เพราะ warning ใน log ตอน boot ไม่มีใครอ่าน และจะรู้ว่ามันแปลว่าอะไรตอนสายไปแล้ว
มีเทสต์คุม 5 ข้อเฉพาะเรื่องนี้ · ทดสอบจริงแล้วทั้งสองทาง (ปฏิเสธ / ขึ้นได้)

**ตอบคำถาม "รันบนเว็บได้ไหม":** ได้ · `docs/deploy.md` สรุปว่า
Render/Railway/Fly/VPS + Supabase คือทางที่ถูกต้อง (~150-250฿/เดือน) ·
Cloudflare Tunnel เปิดจากมือถือได้ฟรีโดยไม่ต้องย้ายอะไร ·
**Vercel/Netlify/Cloudflare Workers ใช้ไม่ได้** เพราะ audit ใช้เวลาเป็นนาที
เกิน timeout ของ serverless ทุกเจ้า และ runtime ก็ไม่รองรับ

### Dashboard (รอบก่อนหน้า) — สลับลำดับมาทำก่อน M4/M5 โดยตั้งใจ

**เหตุผล:** เครื่องมือรัน audit ได้ตั้งแต่ M1 แต่ผลลัพธ์ออกมาเป็น log กับแถวใน Postgres
ซึ่งเอาไปคุยกับลูกค้าไม่ได้ · `CLAUDE.md §1` เขียนไว้เองว่าเกณฑ์ตัดสินฟีเจอร์คือ
*"ทำให้ลูกค้าอยากโทรกลับไหม"* และ §8 เขียนว่า *"คอขวดจริงคือการขาย ไม่ใช่จำนวนฟีเจอร์"*
M4 (GBP) เพิ่มข้อมูล แต่ไม่ทำให้ audit ที่มีอยู่แล้วขายได้ — UI ทำ

```bash
pnpm dash          # http://127.0.0.1:4321 — worker รันอยู่ในโปรเซสเดียวกัน
```

**3 หน้า และสองหน้าหลังเป็นคนละเอกสารกันโดยตั้งใจ:**

| หน้า | ใครอ่าน | มีอะไร |
|---|---|---|
| `/` | เรา | งานตรวจทั้งหมด คะแนน จำนวนวิกฤต ต้นทุน + ฟอร์มเริ่มงานใหม่ |
| `/audits/:id` | เรา | ผลเต็ม: rule code, evidence JSON, keyword, คู่แข่ง, ต้นทุนแยกตาม provider |
| `/audits/:id/report` | **ลูกค้า** | หัวข้อ + วิธีแก้ · พิมพ์เป็น PDF ได้ · **ไม่มี rule code / evidence / ต้นทุน** |

หน้ารายงานไม่ได้ซ่อนด้วย CSS แต่ไม่ render ออกมาเลย — มีเทสต์คุมว่า `CVR-001`
และ `pages_without_tel_link` ต้องไม่โผล่ในหน้านั้น

**ไม่มี build step** — ไม่มี React ไม่มี Next.js ไม่มี bundler เป็น HTML ที่ server
render พร้อม CSS inline สเปกระบุ Next.js ไว้ที่ M6 ซึ่งยังถูกสำหรับงานนั้น
(เว็บสาธารณะ ฟอร์มให้คนแปลกหน้ากรอก ระบบสมาชิก) แต่หน้าจอที่เราใช้เองบนเครื่องตัวเอง
build step คือความเสี่ยงล้วน ๆ ในเช้าวันที่ต้องไปหาลูกค้า — และ HTML ธรรมดาพิมพ์เป็น PDF
ได้ในตัว ซึ่งเป็นวิธีที่รายงานไปถึงลูกค้าจริง ๆ

**สีและการอ่าน:** ใช้ status palette ที่ผ่าน validator แล้ว · ตัวเลข hero 1 ตัวต่อหน้า ·
meter ของแต่ละหมวดใช้สีตามระดับคะแนน · **badge ความรุนแรงมี 3 ช่องทาง** (คำไทย + สัญลักษณ์ + สี)
เพราะ validator บอกว่าสี warning กับ serious ห่างกันแค่ ΔE 13.6 ต่ำกว่าเกณฑ์ 15
คนสายตาปกติก็แยกยาก — ห้ามให้สีเป็นช่องทางเดียว

**เรื่องที่สำคัญที่สุดในหน้านี้:** หมวดที่ยังไม่ได้วัด (local / content / visibility
เมื่อยังไม่มี key) **แสดงเป็นแถบลายทแยงพร้อมคำว่า "ยังไม่ได้วัด" ไม่ใช่แถบคะแนน 50**
ถ้าวาดเป็น 50 สีเหลือง เท่ากับบอกเจ้าของเว็บว่าเขาสอบตกในเรื่องที่เราไม่เคยตรวจ
ซึ่งเป็นบั๊กเดียวกับที่ scoring v2 มีไว้แก้ · หน้ารายงานของลูกค้าตัดหมวดพวกนี้ออกทั้งแถว

**ความปลอดภัย:** `WEB_HOST` = `127.0.0.1` โดยตั้งใจ **ไม่มีระบบล็อกอิน** และมีข้อมูล
ลูกค้าทุกรายอยู่ในนั้น · มี CSP, `noindex`, escape ทุกจุดที่ข้อความจากฟอร์มลงหน้า (มีเทสต์)

**เก็บกวาดระหว่างทาง:** ย้าย `normaliseDomain` เข้า `core/crawl/domain.ts` เพราะตอนนี้
มีสองทางเข้าที่รับโดเมนจากคน (CLI กับฟอร์ม) ถ้าสองที่ normalise ไม่เหมือนกัน
ลูกค้ารายเดียวจะกลายเป็นสองแถวใน `clients` โดยไม่มีใครรู้

### M3 (รอบก่อน)

- `llm/router.ts` — 2 tier (cheap/smart) ชื่อรุ่นจาก `.env` · บังคับ JSON → zod →
  retry 1 ครั้งโดยส่ง error กลับไป → คืน null ให้ caller ใช้ fallback ของตัวเอง
  **บันทึก `model` / `prompt_hash` / tokens ลง `api_calls` แต่ไม่เก็บตัว prompt**
  (prompt มีเนื้อหาเว็บลูกค้าอยู่)
- `keywords/seed.ts` — สร้าง keyword จากหน้าบริการของลูกค้าเอง เป็น pure function
  **ทำงานได้โดยไม่มี API key เลย** ตัดชื่อแบรนด์ ตัดพื้นที่ แล้วต่อพื้นที่กลับเป็น variant
- `serp/dataforseo.ts` — volume + อันดับ · zod ทุก response · ยิงเป็น batch
- pipeline **06-keywords · 07-serp · 10-competitors** (รวมเป็น 10 ขั้น)
- rules **CON-001..005 + CMP-001..003** (รวมเป็น 35 ข้อ)
- 04-classify ส่งหน้าที่กฎตัดสินไม่ได้ให้ LLM cheap **แบบ batch เดียว** (เพดาน 40 หน้า)

### สิ่งที่การรันจริงจับได้ (ไม่ใช่เทสต์)

### รอบตรวจซ้ำ — เจอบั๊กที่ PGlite จับไม่ได้

รันสคีมาและ pipeline ทั้งชุดกับ **Postgres 16 ตัวจริง** ก่อนส่งงาน เจอบั๊กที่เทสต์เดิม
มองไม่เห็นโดยโครงสร้าง: **`jsonb` ถูกเก็บเป็น string** บน production driver
(`jsonb_typeof(evidence)` = `"string"`, `evidence->>'key'` คืนค่าว่าง)

สาเหตุ: driver สองตัวรับพารามิเตอร์ jsonb คนละแบบ และไม่มีตัวไหน error —
`postgres.js` เดาชนิดจากค่า JS (ส่ง string เข้าไป = ได้ JSON scalar) ส่วน PGlite ต้องการ string
อ่านกลับด้วย JS ได้ผลถูกทั้งคู่ บั๊กจึงเงียบสนิท **ใส่ `::jsonb` cast อย่างเดียวไม่พอ**

แก้ด้วย `json()` wrapper ใน `db/client.ts` (Symbol) แล้วแต่ละ driver จัดการเอง +
`db/postgres.integration.test.ts` ที่รันเมื่อมี `DATABASE_URL` เท่านั้น
**บทเรียน:** เทสต์ที่รันบน driver เดียว พิสูจน์เรื่องที่ต่างกันระหว่าง driver ไม่ได้

เจออีกอย่างระหว่างตรวจ: `.gitignore` เขียนคอมเมนต์ต่อท้ายบรรทัด ซึ่ง git ไม่รองรับ —
`.data/`, `.cache/`, `.ctx-tests`, `reports/` จึงไม่ถูก ignore จริง และ `.ctx-tests`
(ไฟล์ที่ generate ใหม่ทุกครั้งที่เทสต์) ถูก commit ไปแล้ว แก้ทั้งสองอย่าง

### tag ของ milestone — ต้องสร้างเองครั้งเดียว

git proxy ของ session ปฏิเสธการ push tag (403) push ได้แต่ branch
commit อยู่บน remote ครบแล้ว ขาดแค่ ref ของ tag รันครั้งเดียวหลัง clone:

```bash
git tag -a wgi-m0 -m "wgi-audit m0" efaa0149e377f05b10cfdc3862c7d01ce97f701f
git tag -a wgi-m1 -m "wgi-audit m1" 50248585121da8733f516f56e07de50e654b1318
git tag -a wgi-m2 -m "wgi-audit m2" e434b4304c282b024db1c5f940bca2f85ebede00
git tag -a wgi-m3 -m "wgi-audit m3" 0f4f749eb87c35e45144c67914819da6d4ed2cac
git push origin wgi-m0 wgi-m1 wgi-m2 wgi-m3
```

**ถ้าจะแยกออกเป็น repo ของตัวเองภายหลัง:** `git subtree split --prefix=wgi-audit -b wgi-only`
